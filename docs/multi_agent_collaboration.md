# 多 Agent 并发协作规则

本仓库经常有多个 AI agent 同时工作、各自实现不同功能。所有 agent 遵守以下规则。

## 基本态度

1. **禁止全仓级单方面操作** — 任何 agent 不得擅自做波及整个仓库的改动：
   `git stash`、大规模重构、成批移动/重命名文件、清空重建 build 目录。
   这类操作先和用户协调。
2. **文件的"意外"变化是常态** — 其他 agent 可能正在同时编辑。两次操作之间
   文件内容变了、冒出未知文件，不要当作错误或损坏处理。
3. **遇到异常先停下问** — 碰到冲突、疑似丢失的改动、意外状态，停下来问
   用户，不要单方面"修复"。

## 让路细则

- **构建互斥**：重编译前确认没有其他 agent 正在跑 ninja / 测试 / 渲染——
  并发构建会互相踩 `build/` 与 `Binaries/`。有人在跑就等它结束。
- **GPU 互斥**：同一时刻只跑一个重 GPU 任务（渲染、地形解算等）。长 RT
  dispatch（如云渲染）会冻结远程控制，跑重任务前先征得用户同意。
- **提交纪律**：只提交自己名下的文件；工作区里来历不明的改动绝不能顺手
  一起 commit。agent 提交前必须获得用户明确批准。
- **DLL 锁**：`hd_RUZINO*.dll` 链接失败（LNK1104）通常是别的进程占用——
  残留的 python 测试进程可以结束；用户正在运行的 Ruzino.exe 不要杀，
  请用户自己关。

## 历史事故（为什么有这些规则）

2026-08-04：一个 agent 的并发 `git reset` 抹掉了另一个 agent 未提交的
工作。文件"莫名"回到 HEAD 状态时，先查 `git reflog` 找回，不要重复劳动。
